## 🔴 Read this first: no form on the deployed site currently works

The Vercel project `tobeehonest-site` had **zero environment variables set**. `airtableConfig()`
throws a 503 when `AIRTABLE_TOKEN` or `AIRTABLE_BASE_ID` is absent, so every submission —
deck, prints, marketplace, commissions, hive, book — returns *"The submission system is not
configured yet."* to the visitor. `RESEND_API_KEY` is also unset, so no alert emails are sent.

This is not new breakage from this pass. It has been true of every deploy.

**Root cause:** an Airtable Personal Access Token has never been created for this project.
The Airtable tooling used during development authenticates via an OAuth connector that the
deployed serverless functions cannot use.

### To make the forms live — three commands

`AIRTABLE_BASE_ID` is already set (all three environments). Remaining:

1. Create an Airtable PAT at https://airtable.com/create/tokens
   - scope: `data.records:write` (add `data.recordComments:write` only if needed later)
   - access: base **To Bee Honest** (`appiWkCMQz8kfJvOl`)
2. ```
   cd ~/tobeehonest-site
   vercel env add AIRTABLE_TOKEN production      # paste the PAT
   vercel env add RESEND_API_KEY production      # value is in ~/.foreman-secrets/env
   ```
   Repeat for `preview` if you want the preview URL to record too.
3. Redeploy — env changes do not apply to existing deployments:
   ```
   vercel --yes            # preview
   ```

Until step 2 is done, **do not demo the forms to Nicolas.** They will show an error.

## What changed in this pass

**Book pre-order — built (was missing entirely).**
The book tier quoted *"Launch price: $59"* and offered no way to act on it — the only tier
with a price and no button. It now follows the deck's shipped pattern exactly: quantity,
edition (Paperback / Signed by Nicolas), name, email, address; nothing charged.

Assumption stated plainly: the book has **no print run and no fulfillment vendor**. Records in
Book Orders are expressions of interest Nicolas can honour or decline with no refund to
process. The alert email and the Airtable table description both say so in as many words, and
the `Price` column is deliberately left blank on submission so it never reads as money already
collected. If Nicolas wants notify-only instead of a shipping address, that's a small change.

**Three Airtable tables created** in base `appiWkCMQz8kfJvOl`:
`Commission Enquiries`, `Hive Signups`, `Book Orders`. Commissions and hive signups previously
wrote nowhere — they existed as forms that emailed and vanished. All three are wired as code
defaults, so no env var is needed for them.

**Hidden-button bug — fixed.** `.tag-btn{display:inline-flex}` was silently defeating the
`hidden` attribute (which is only a user-agent `display:none`, the weakest cascade origin). So
"Order the Deck", "Submit your creation" and "Pre-order the Book" all stayed on screen next to
the form they had just opened. One rule — `.tag-btn[hidden]{display:none}` — fixes all three.

**Stale marker removed.** The hive form still carried `data-placeholder="wire-to-provider"`
long after it had been wired.

Tests: **34/34 passing** (4 new, covering the book path, the Edition/Variant column split, and
the `TBH-B` order-id prefix).
